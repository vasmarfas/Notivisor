# Notivisor

Уведомления с телефона внутри VR-шлема — в том числе поверх запущенной игры. Одно приложение
ставится на оба устройства и связывает их напрямую по Bluetooth или Wi-Fi. Без аккаунта, без
сервера, ничего не покидает эти два устройства.

[English version](README.md)

**❤️ Поддержать проект:** [`SUPPORT.md`](SUPPORT.md). **🔒 Приватность:** [
`privacy-policy.md`](privacy-policy.md). **📜 Условия:** [`terms.md`](terms.md).

## Задача

Снять шлем, чтобы посмотреть, кто написал, — значит выйти из игры. Существующие решения предлагают
либо поставить мессенджер внутрь VR, либо гонять уведомления через чьё-то облако.

Notivisor не делает ни того, ни другого. Стороннее приложение на Horizon OS не может рисовать поверх
иммерсивного: `SYSTEM_ALERT_WINDOW` даёт 2D-панель, которую VR не композитит, а `XR_EXTX_overlay`
сторонним разработчикам недоступен. Единственный слой, который система всё ещё рисует поверх игры, —
её собственная шторка уведомлений. Поэтому телефон читает свои уведомления и передаёт их шлему, а
тот
публикует их у себя заново на канале с высокой важностью. В этом весь приём — и поэтому всплывашка
появляется там, где больше ничего появиться не может.

## Возможности

- Любое уведомление телефона всплывает в шлеме поверх происходящего
- Выбор приложений: пересылать всё, кроме снятых, либо только отмеченные
- Снятое на телефоне гаснет и в шлеме
- Отдельный канал уведомлений на каждое приложение-источник — заглушить один источник можно штатными
  настройками шлема
- Повторы отсеиваются, счётчики непрочитанного и прогресс загрузок не сыплются градом
- Bluetooth LE по умолчанию, Wi-Fi — если так удобнее
- Шифрование AES-256-GCM ключом, выведенным из кода сопряжения
- Завершение работы, которое действительно всё останавливает и убирает приложение из фона

## Требования

- Телефон: Android 8.0 (API 26) или новее
- Шлем: Meta Quest 3 или 3S; другие шлемы на Android работают с оговоркой ниже
- Доступ к уведомлениям на телефоне и снятое ограничение батареи
- Bluetooth на обоих устройствах либо общая сеть Wi-Fi

Разрабатывалось на Galaxy Z Flip 4 (Android 16) и Quest 3 с Horizon OS v206.

## Установка

Скачайте APK из [Releases](../../releases) и поставьте на **оба** устройства — приложение само
определит, где оно запущено. Для сайдлоада на Quest нужен режим разработчика и `adb install` либо
что-то вроде SideQuest.

Сборка из исходников:

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Нужен JDK 17, остальное подтянет Gradle wrapper.

## Настройка

**На телефоне** приложение открывается со списком:

1. **Доступ к уведомлениям** — без него Android не даст читать уведомления никакому приложению.
2. **Работа без ограничений батареи** — иначе система остановит приложение примерно через минуту
   после того, как погаснет экран (особенно на Samsung). Из списка есть переход прямо в нужный
   экран.
3. **Разрешения Bluetooth.**

Дальше нажмите **Подключить шлем** — появится QR-код.

**В шлеме** откройте приложение и нажмите **Сканировать QR**. В коде передаются код сопряжения, тип
соединения и адрес, так что подгонять настройки вручную не нужно. Если камера шлема недоступна,
введите 16 цифр вручную.

После перезагрузки оба устройства поднимают свою сторону сами.

## Если не работает

**«Коды не совпадают».** Устройства соединились, но не понимают друг друга. Отсканируйте QR заново.
Переустановка одной из сторон стирает её код.

**Шлем не находит телефон.** Проверьте, что обе стороны на одном типе соединения. Если Bluetooth
не устанавливается — переключите обе на Wi-Fi; шлему тогда нужен адрес телефона, он тоже есть в QR.

**Уведомления перестают приходить за ночь.** Почти всегда это ограничения батареи на телефоне.
Проверьте карточку настройки заново — некоторые производители сбрасывают это после обновления
системы.

**На Pico не сканируется QR.** Работает всё, кроме сканирования: Pico открывает камеру только
авторизованным корпоративным сборкам. Введите код сопряжения вручную.

## Приватность

Текст уведомлений идёт с телефона на шлем и больше никуда. Ни аккаунта, ни аналитики, ни сетевых
запросов помимо прямого соединения. Канал зашифрован AES-256-GCM ключом из кода сопряжения — быть
в зоне действия Bluetooth недостаточно, чтобы что-то прочитать. Подробности — в
[`privacy-policy.md`](privacy-policy.md).
